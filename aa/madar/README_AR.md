# مَدار — منصة إدارة مشاريع الطلاب

## تحديث الربط
تم إدخال إعدادات مشروع wepproject-5b510 وتفعيل mode: firebase. لا تحتاج تعديل config.js لهذه النسخة. وضع العرض التجريبي أدناه اختياري ويتطلب إعادة mode إلى demo. لم يُختبر إنشاء حساب فعلي على مشروعك. بعد استبدال الملفات اضغط Ctrl+F5 وشغّل الموقع عبر localhost أو HTTPS، وتأكد من إنشاء Firestore ونشر قواعده.


المشروع كامل المصدر بواجهات عربية RTL، HTML وCSS وJavaScript، وFirebase Authentication وFirestore وStorage للخدمات الخلفية. لا يحتاج PHP أو MySQL، ولا يحتوي خادماً بلغة PHP. الصفحات داخل تطبيق واحد بروابط # قابلة للتنقل، وليست ملفات HTML منفصلة.

## ابدأ خلال دقيقة على ويندوز
1. فك ضغط الملف.
2. افتح المجلد في VS Code وشغّل index.html باستخدام Live Server، أو انسخ المجلد إلى C:\xampp\htdocs\madar ثم شغّل Apache وافتح http://localhost/madar/.
3. بديل باستخدام Python: افتح Terminal داخل المجلد واكتب `python -m http.server 8000` ثم افتح http://localhost:8000.
4. اضغط تجربة طالب أو مشرف أو لجنة أو مدير. لا تحتاج كلمات مرور للعرض التجريبي.
5. لا تفتح index.html بالنقر المزدوج بصيغة file:// لأن ملفات JavaScript تستخدم modules.

## الخصائص
- تسجيل مستقل للطالب والمشرف، بريد وكلمة مرور، ويوزر فريد 3–24 حرفاً إنكليزياً صغيراً يبدأ بحرف. الدخول بالبريد؛ اليوزر للبحث والتواصل.
- استعادة كلمة المرور بالبريد من Firebase.
- 12 صفحة رئيسية، إضافة إلى تفاصيل المشروع والدخول والتسجيل.
- لوحة تحكم، مشاريع، مهام بثلاث مراحل، تسليمات وروابط ومستندات، محادثة خاصة، تعليقات المشروع، تقويم، تقييمات، توصيات حسابية، تقارير CSV وطباعة PDF، دليل مستخدمين، إعلانات، إعدادات.
- نسبة الإنجاز = عدد المهام المكتملة ÷ مجموع مهام المشروع × 100. جميع المهام لها الوزن نفسه، ومن دون مهام تكون النسبة صفراً.
- تحريك بطاقات وانتقالات وصفحات ومؤشرات تقدم وأشكال مدارية، مع احترام تفضيل تقليل الحركة.
- الوضع المحلي يخزن البيانات في المتصفح ويزامن التبويبات على نفس الأصل، وليس بين أجهزة مختلفة.
- Firebase يستخدم onSnapshot للمزامنة بين الأجهزة ولا ينسخ بيانات العرض إلى قاعدة البيانات الحقيقية.
- المساعد يحلل المواعيد والمهام بقواعد محددة؛ ليس نموذج ذكاء اصطناعي توليدياً ولا يحتاج API مدفوعاً.

## ربط Firebase للحسابات الحقيقية والمزامنة
1. أنشئ مشروعك من https://console.firebase.google.com/ ثم أضف Web App.
2. افتح Authentication ثم Sign-in method وفعّل Email/Password.
3. أنشئ Cloud Firestore database.
4. من إعدادات مشروع Firebase > Your apps انسخ كائن firebaseConfig.
5. ضع القيم داخل `assets/config.js` في firebase، وبدّل mode من demo إلى firebase. هذه إعدادات تطبيق ويب؛ لا تضع service account أو مفتاحاً خاصاً في المتصفح.
6. أضف اسم نطاق الاستضافة وlocalhost عند الحاجة إلى Authorized domains في Authentication Settings.
7. انشر قواعد Firestore المناسبة من قسم Rules؛ توجد نسختان موضحتان أدناه.
8. لرفع الملفات فعّل Firebase Storage وطبّق storage.rules. تحقق من شروط الخدمة والخطة داخل حسابك. يمكنك استخدام روابط ملفات أو مستودعات بدلاً من رفع الملفات إذا لم تفعل Storage.
9. أعد تحميل الموقع وأنشئ حساب طالب وحساب مشرف ببريدين مختلفين. ابحث عن المشرف بواسطة @username ثم افتح محادثة.
10. أنشئ مشروعاً وحدد المشرف. أضف المهام وغيّرها إلى مكتملة لترى نسبة الإنجاز تتحدث.

## قواعد الوصول — اقرأ قبل استخدام بيانات حقيقية
`firestore.rules` يحتوي قواعدك المفتوحة تماماً كما طلبت: allow read, write: if true. إنها للاختبار فقط. يستطيع أي شخص قراءة وتغيير كل البيانات حتى الرسائل؛ خصوصية واجهة المحادثة لا تحمي قاعدة بيانات مفتوحة.

`firestore.production.rules` بديل يطلب تسجيل الدخول، يقيد إنشاء الرسائل بالمرسل وقراءتها بطرفي المحادثة، ويقيد التعديل بحسب الأدوار وعضوية المشروع. firebase.json يشير لهذا البديل افتراضياً. لا تنشر القواعد المفتوحة بالتزامن معه لأن قاعدة السماح العامة تلغي الحماية.

حدود النسخة البديلة: بيانات المشاريع والمهام والتسليمات والتقييمات مقروءة لكل حساب مسجل داخل المؤسسة، وإن كانت الواجهة تعرض المشاريع المسندة فقط. الملفات متاحة للحسابات المسجلة وروابط تنزيل Firebase قابلة للمشاركة. ليست هذه النسخة عزلاً سرياً لكل فريق. كما يسمح التسجيل الذاتي بدور مشرف؛ للمؤسسة التي تتطلب اعتماد الدكاترة ينبغي إضافة دورة موافقة إدارية قبل فتح التسجيل العام. لم تُختبر القواعد على مشروع Firebase حي أو محاكي داخل هذه الجلسة؛ راجعها واختبرها قبل التشغيل ببيانات فعلية.

## تفعيل الأدمن واللجنة
- سجّل حسابك أولاً.
- افتح Firestore > profiles > وثيقة UID الخاصة بحسابك.
- غيّر role إلى admin من Firebase Console باستخدام حساب مالك المشروع.
- من صفحة دليل المستخدمين يستطيع الأدمن تعيين student أو doctor أو committee للحسابات الأخرى.
- لا يوجد حساب أدمن سري أو كلمة مرور عامة في النسخة الحقيقية.

## الرفع إلى استضافة
على استضافة ملفات ثابتة أو استضافة PHP: ارفع index.html ومجلد assets فقط إلى public_html أو المجلد العام. لا يحتاج المشروع بناء npm. استعمل HTTPS. إعدادات Firebase تبقى في assets/config.js وتجب تهيئتها قبل الرفع.

Firebase Hosting: يمكن استخدام إعداد firebase.json مع أدوات Firebase CLI بعد اختيار مشروعك. يحتوي public على جذر المجلد ويستثني الاختبارات والقواعد والدليل. مثال: `firebase use --add` ثم `firebase deploy --only hosting,firestore:rules,storage` بعد إعداد الخدمات ومراجعة القواعد. لا توجد بيانات حساب أو مشروع Firebase مرفقة في الملف.

## الملفات
- index.html: نقطة الدخول.
- assets/style.css: التصميم والحركات والاستجابة للموبايل والطباعة.
- assets/app.js: الصفحات والنماذج والتفاعلات.
- assets/store.js: Firebase والبيانات المحلية والحسابات ورفع الملفات.
- assets/domain.js: نسب الإنجاز ومخاطر التأخير والتحقق.
- assets/config.js: إعدادات الاتصال الوحيدة التي تحتاج إدخالها.
- assets/logo.svg: الشعار المحلي.
- firestore.rules: قواعد الاختبار المفتوحة المطلوبة.
- firestore.production.rules: القواعد المقيدة مع الحدود المذكورة.
- storage.rules وfirebase.json: إعدادات خدمات Firebase والنشر.
- tests/domain.test.js: اختبارات الحساب والتحقق؛ تشغيلها بـ npm run check عند وجود Node.

## اختبار بعد الربط من جهازين
سجّل الطالب في الجهاز الأول والمشرف في الثاني. أنشئ المشروع وحدد المشرف، ثم تأكد من ظهوره له. أرسل رسالة ليوزر المشرف وتحقق من وصولها وردّه. أكمل مهمة وتحقق من تغير الداشبورد في الجهازين. ارفع تسليماً وراجعه من حساب المشرف. اختبر بريد استعادة كلمة المرور، عدم تكرار اليوزر، رفض الوصول للرسائل من حساب ثالث، وانقطاع الإنترنت وإعادة الاتصال.

## حدود التحقق والاعتماد الخارجي
تم فحص JavaScript واختبارات منطق الإنجاز والمخاطر واليوزر والروابط محلياً، وفُحصت الواجهة في المتصفح. إعداد Firebase الحقيقي واختبار التسجيل والمزامنة السحابية ورفع Storage يحتاج إعدادات مشروعك ولم ينفذ على حساب حي. خط Tajawal من Google Fonts اختياري مع خط بديل محلي، وFirebase SDK يحمل من gstatic عند تشغيل الوضع السحابي. العرض المحلي لا يتطلب Firebase.
